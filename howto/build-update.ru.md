# Сборка обновления для всех устройств

Когда upstream [meshcore-dev/MeshCore](https://github.com/meshcore-dev/MeshCore)
выпускает новый релиз, пересоберите прошивку наблюдателя для всех
поддерживаемых плат и перепрошейте узлы.

## Стандартный сценарий обновления

```sh
cd MeshCore
git checkout mqtt-uplink
./scripts/build-observer_meshcoretel.sh
```

Без аргументов скрипт:

1. забирает upstream и выбирает **последний тег `repeater-v*`**;
2. **ребейзит `mqtt-uplink` на этот релиз** — отличия форка ~19 строк в 3
   файлах плюс новые файлы, поэтому конфликтов почти не бывает; при конфликте
   скрипт останавливается и печатает, что делать (`git rebase --continue`
   после разрешения, или `git rebase --abort` для отмены);
3. собирает **все 17** окружений `*_observer_meshcoretel`;
4. складывает свежие образы в `out/observer-meshcoretel/<новая-версия>/<env>/`.

Чтобы собрать под конкретный релиз, а не новейший:

```sh
./scripts/build-observer_meshcoretel.sh repeater-v1.19.0
```

Только одна плата (быстрая проверка перед полной матрицей):

```sh
./scripts/build-observer_meshcoretel.sh repeater-v1.19.0 --env Heltec_v3_observer_meshcoretel
```

## Что проверить перед прошивкой парка

1. **Размеры сборки** — каждое окружение печатает RAM/Flash; всё, что
   подскочило к > ~90% flash, стоит рассмотреть.
2. **Поведение нового релиза upstream** — прочитайте релизные заметки;
   изменения радио/ретрансляции касаются и наблюдателей.
3. **Сначала одна канареечная нода**: прошейте одну представительную плату,
   проверьте `get mqtt.status` и поток пакетов на meshcoretel.ru, затем
   раскатывайте на остальные.

## Перепрошивка узла (чистая установка)

Поддерживаемый путь — **свежая/чистая установка**: она снимает все вопросы
совместимости прошивок (старые версии, OTA-слоты, раскладки разделов):

1. На `flasher.meshcore.dev` сначала выберите плату, затем пункт
   **Custom Firmware** и укажите образ `-merged.bin` из каталога новой
   версии (см. [build-from-scratch.ru.md](build-from-scratch.ru.md),
   раздел «Прошиваем плату»).
2. Или локально:

   ```sh
   esptool.py --chip esp32s3 --port /dev/ttyUSB0 --baud 921600 erase_flash
   esptool.py --chip esp32s3 --port /dev/ttyUSB0 --baud 921600 \
       write_flash 0x0 out/observer-meshcoretel/<версия>/<env>/<EnvName>-v<версия>-<sha>-merged.bin
   ```

Чистая установка стирает файловую систему: узел генерирует **новую identity**,
все настройки сбрасываются — после прошивки повторите
[настройку](setup.ru.md) и имейте в виду: узел появится под тем же IATA, но
с новым pubkey.

## Синхронизация форка и документации

- Если rebase потребовал ручных правок — это сигнал: проверьте, не поменял ли
  upstream то, на чём держится наш модуль (сигнатура конструктора `MyMesh`,
  размеры reply-буферов CLI и т.п.), и поправьте `ObserverMesh`/`MQTTUplink`.
- Обновляйте ожидаемые размеры/список плат в этом howto, только если реальность
  изменилась.
