# Настройка прошитого узла

Разовая настройка через serial-консоль (или удалённо через mesh, через админ
CLI, если узел уже есть в ваших контактах). Настройки сохраняются между
перезагрузками и обновлениями прошивки.

## 1. Подключаемся к узлу

Используйте companion-приложение MeshCore: узел после загрузки отправляет
advert и появляется в списке нод. Откройте его и войдите как админ
ретранслятора — на свежем узле пароль по умолчанию `password`, сразу смените
его командой `password <новый>`. Далее вводите команды ниже в консоли
ретранслятора.

Serial-консоль (115200 бод) — запасной вариант, если узел в приложении ещё не
появился — например, когда его радионастройки не совпадают с вашим регионом
(`set freq` / `set bw` / `set sf` / `set cr` намеренно доступны только по
serial).

## 2. Настраиваем WiFi, IATA, проверяем

Всё делают три команды:

```
set wifi.ssid ВашаСеть
set wifi.pwd ВашПароль
set mqtt.iata KVX
```

- `iata` — код локации в теме MQTT (`meshcore/<IATA>/<pubkey>/...`); до его
  установки публикация выключена. Используйте код, о котором договорилась ваша
  сеть (для Кировской сети: `KVX`).
- Брокер (meshcoretel) **включён по умолчанию** — серверы и учётные данные
  настраивать не нужно.

Проверяем:

```
get mqtt.status
```

Сразу после `set mqtt.iata` будет примерно так:

```
> wifi:up ntp:wait iata:KVX meshcoretel:wait eu:off us:off tx:off pkt:0 pub:0 drop:0 q:0/8 heap:118000
```

Через ~30–60 секунд должно стать:

```
> wifi:up ntp:up iata:KVX meshcoretel:up eu:off us:off tx:off pkt:12 pub:12 drop:0 q:0/8 heap:110000
```

Значения полей: `wifi` — станция, `ntp` — часы синхронизированы (публикация
включается только после `up`), состояния брокеров —
`up`/`wait`/`retry`/`backoff`/`off`/`invalid-iata`, `pkt` — услышано пакетов,
`pub` — опубликовано, `drop` — потеряно (очередь полна / брокер недоступен
> 60 с), `q` — глубина офлайн-очереди, `heap` — свободная память.

Если `pkt` растёт, а `meshcoretel:up` — всё работает. Проверьте, что узел
появился на meshcoretel.ru под вашим IATA.

## 3. Дополнительные настройки

```
set mqtt.tx advert      # публиковать и свои реклама-пакеты (видимость на картах)
set mqtt.raw on         # публиковать сырые кадры (больше трафика, по согласию)
set mqtt.packets off    # остановить публикацию разобранных пакетов (вкл. по умолчанию)
get wifi.status         # ip, rssi, качество сигнала
mqtt recover            # пересобрать WiFi + соединения с брокерами с нуля
reboot                  # настройки сохраняются
```

### Что публикуют эти потоки

- **`mqtt.packets` (вкл. по умолчанию — основной телеметрический поток)**: по
  одному JSON на каждый услышанный кадр с RF-измерениями — `packet_type`
  (advert / текст / ACK / path / trace…), `route` D/F, `SNR`/`RSSI` на данном
  наблюдателе, `score`, `duration`, `hash`. Содержимое остаётся зашифрованным;
  сервер декодирует то, для чего у него есть ключи. Именно этот поток строит
  карту покрытия и статистику по линкам — для наблюдателя держите его
  включённым. Пакет, услышанный через несколько ретрансляторов, публикуется
  по одному разу на каждый приём (SNR/RSSI разные — так и задумано).
- **`mqtt.raw` (выкл. по умолчанию)**: те же кадры «как есть» — голый hex без
  измерений — в отдельную тему `/raw`. Нужен для отладки своих декодеров или
  захвата трафика, который парсер сервера не понимает. Он дублирует поле
  `raw`, которое уже есть внутри `packets`, и удваивает исходящий трафик —
  без необходимости не включайте. В отличие от `packets`, `raw` не ставится в
  офлайн-очередь при недоступности брокера.

Радиопараметры должны совпадать с региональными настройками вашей сети —
следуйте рекомендациям meshcoretel.ru для региона (KVX); не копируйте
радиопараметры со страниц других регионов.

## Ручное применение KVX-дефолтов (уже настроенные узлы)

Автозасев выполняется только на узле без сохранённых настроек. Если узел
настраивался раньше (или есть подозрение, что засев не применился), вставьте
этот список в serial-консоль или консоль ретранслятора в приложении:

```
set radio 868.731 62.5 8 8
set path.hash.mode 1
set cad on
set txdelay 2
set rxdelay 5
set loop.detect minimal
set tx 22
set advert.interval 240
set flood.advert.interval 24
set name KRV_repeater
set mqtt.iata KVX
region put ru
region put kvx ru
region allowf *
region save
reboot
```

(`set radio` отвечает "OK - reboot to apply"; финальный `reboot` применяет
радиопараметры. Строку `mqtt.iata` опустите на ванильных сборках `_kvx`.
Проверка: `get radio`, `get freq`, `get name`, `region list`.)

## Примечания

- **KVX-сборки** (`*_kvx`, `*_observer_kvx`) при первой загрузке
  ненастроенного узла вносят региональные дефолты (радио 868.731/62.5/SF8/CR8,
  path.hash.mode 2, cad, txdelay 2, rxdelay 5, имя `KRV_repeater`, регионы
  `ru`/`kvx`, iata `KVX`) и сами перезагружаются. Свежий узел сразу
  сконфигурирован — как правило, достаточно задать WiFi. У всех новых узлов
  одинаковое имя `KRV_repeater`: переименуйте каждый узел командой
  `set name <уникальное-имя>`. Повторный засев не выполняется никогда после
  первых сохранённых настроек.

- **Питание**: наблюдатель намеренно не спит (WiFi должен оставаться
  подключённым). Узлы с включённым `powersaving_enabled` тоже не засыпают,
  пока активен uplink.
- **Удалённое администрирование**: всё выше работает через mesh прямо из
  приложения, например `mqtt recover` из дома. Одно ограничение: вывод
  `get mqtt.status` длинный и через mesh может обрезаться — полную строку
  смотрите по serial.
- **Безопасность**: пароль WiFi хранится на устройстве (по CLI не
  возвращается); учётные данные meshcoretel — общедоступные по дизайну
  брокера. Физический доступ к узлу = доступ к его конфигурации.
